# 写作流程与任务路由

本文件补充 `SKILL.md` 的控制流程。先判断任务强度和使用场景，再选择最少的步骤与参考资料。不要把这个流程当作每次都必须完整展示给用户的问卷。

## 快速、标准与深度任务

| 类型 | 例子 | 访谈 | 判断与交付 |
|---|---|---|---|
| 快速 | 改标题、改一句话、纠错、把一条消息说得更礼貌 | 只有当场景确实改变措辞时，问一个问题 | 一行判断后同一轮给结果。 |
| 标准 | 邮件、社交帖、短文、已有稿件的改写或审稿 | 补齐任务、场景、目标中缺失的关键项 | 先给简短判断；用户需要时再扩展。 |
| 深度 | 长文、演讲、小说章节、人物稿、情绪写作、含数据/引语/敏感经历的文本 | 先确认任务、场景、目标、材料、约束与修订范围 | 给判断后默认等待确认，除非用户要求直接产出。 |

## 需求与场景访谈

标准和深度任务优先确认：

1. **需求**：构思、结构、起草、改写、润色还是审稿？已有原文、材料或想法是什么？
2. **场景**：出现在哪里，谁会读/听，他们在什么状态下接触它？
3. **结果与约束**：希望读者理解、感受或采取什么行动？有无篇幅、截止时间、语气、格式、事实、隐私或禁忌要求？

情绪或“人味”任务再确认：真实触发事实、希望强化或收低的情绪、不可虚构或不可美化的内容。用户提供过的信息要先复述确认，只问会改变文本的缺项。

用户说“直接写”时，使用已知信息并标出必要假设。不要把缺少材料当作继续盘问的理由，也不要把假设变成事实。

## 用户资料完整性检查

用户提到附件、文件路径、链接、样稿、截图、扫描件、音视频、表格或“按资料写”时，在写作判断前先做轻量核验。详细状态与降级规则见 [input-materials.md](input-materials.md)。

1. 列出本次交付真正依赖的资料及其用途。
2. 确认每项是可读、缺失、无权限、不可解析、空/截断、版本冲突，还是上下文不全。
3. 判断它是关键资料还是非关键资料，以及缺失会影响事实、声音、引用、结构还是只影响丰富程度。
4. 非关键缺失时继续；关键缺失时只请求一项决定性材料，或按用户意图给不依赖该资料的框架、通用版本或条件化版本。

文件名、链接标题、用户对附件的概述和无法访问的路径都不等于已读取资料。扫描件、图片、音视频若没有可靠文字内容，只能基于已确认的描述继续，不能猜测未提取内容。长资料仅覆盖部分时，要说明阅读范围，不声称已经完成全文判断。

## 写作判断

在标准或深度任务开始前，给出一个小而有用的判断：

```text
写作判断
- 任务与交付：……
- 场景与读者：……
- 核心策略：……
- 材料边界：……
- 修订范围 / 下一步：……
```

判断应该说明选择某种结构、信息密度、语气或情绪路径的理由。快速任务只需一句，例如：“这是面向客户的确认消息，我会保留直接结论，压缩背景，并明确下一步。”

用户资料状态会影响交付时，在判断里增加一行：`资料状态：已读……；未读取/无法使用……；本次仅基于……继续。` 资料状态正常且不影响写作时，无需为了形式而展示它。

## 阅读动能 brief

文章、叙事和标准以上的写作，在 brief 中再写一行：

```text
阅读动能
- 开头承诺：读者为什么现在要继续读？
- 核心张力：哪两个真实的愿望、事实、解释或代价互相拉扯？
- 推进节点：哪些事实/场景会改变读者的认识？
- 峰值：全文最需要被记住或感受到的一处是什么？
- 回报与余波：读者最后得到什么新理解，什么仍不被抹平？
```

这不是要求每篇文章都悬疑或激烈。没有真实冲突时，可以使用好奇、反差、时间限制、观察距离、选择难度或未完成感；若这些也不存在，就删减重复说明，不凭空加戏。

## 从意图到 brief

将已确认信息收束为：

| 项目 | 要回答的问题 |
|---|---|
| 目的 | 希望读者理解、相信、感受或采取什么行动？ |
| 读者 | 谁会读？已经知道什么？会担心或质疑什么？ |
| 载体 | 长文、公众号、口播、演讲、邮件、小说章节，还是别的形式？ |
| 核心承诺 | 全文只能留下哪一个判断、画面或变化？ |
| 阅读体验档位 | 读者应以什么速度和音量读下去：克制观察、稳定张力、强烈推进、轻巧机锋或沉浸叙事？ |
| 材料 | 哪些事实、例子、场景、数据或经验必须出现？ |
| 约束 | 字数、时间、语气、禁用内容、隐私、引用或格式是什么？ |

信息仍缺失时，优先问目的、读者和交付形式。仅在用户明确要求直接开始时采用低风险默认值：普通中文读者、清楚自然、适度具体、短段落、先结论后展开，并说明这是暂定假设。

## 结构选择

结构是读者认识变化的顺序，不是装饰性的模板：

- **解释型**：问题 → 背景 → 关键机制 → 例子 → 结论/行动。
- **观点型**：场景或冲突 → 核心判断 → 证据 → 限制或反方 → 回到判断。
- **叙事型**：稳定状态 → 触发事件 → 欲望与阻力 → 选择 → 新状态或余波。
- **说明/产品型**：读者问题 → 解决方案 → 如何工作 → 证据 → 边界 → 下一步。
- **口播型**：钩子 → 单一主张 → 三个推进点 → 记忆句 → 收束或行动。

为每一节写一句“这一节改变了读者什么认识”。答不出来时，这一节可能是重复、装饰或顺序错误。

文章、散文、叙事、口播和演讲默认先为每一节补一项“读者为什么继续读”：期待什么信息、选择、变化或情绪回报。用户反馈文章“太平”“无聊”或“不抓人”时，再定位是期待、阻力、变化、具体性、节奏还是回报出了问题。连续三节都只有同一种说明功能时，读取 [reader-momentum.md](reader-momentum.md) 做反平淡修订，并先对照其中相近的 Before / After 案例。

## 起草与修订

先完成事实、动作和结构，再调整语言。每段只承担一个主要动作：提出、解释、展示、转折、反驳、决定或收束。段落之间用因果、时间、对比、递进或关系变化连接，不能用“首先、其次、最后”掩盖逻辑缺口。

## 三遍起草法

对标准和深度成稿，按三遍处理：

1. **骨架遍**：只确认核心承诺、材料顺序、段落功能、事实边界和结尾方向；允许句子粗糙，不在此时追求漂亮。
2. **动能遍**：检查开头承诺、真实阻力、信息揭示、段落变化、峰值和回报；删除同义重复，让具体事实和动作替代空泛总结。
3. **声音遍**：调整叙述距离、句长、停顿、词汇、幽默和情绪可见度，再做事实、引用、格式和错别字检查。

如果第二遍没有改变文章的阅读路径，第三遍的逐句润色通常只会把平淡打磨得更光滑。

修订按影响范围从大到小：

1. 目的、读者和场景是否匹配。
2. 核心承诺是否清楚，材料是否围绕它。
3. 段落顺序、论证或叙事推进是否成立。
4. 句子、节奏、用词和衔接是否准确。
5. 标点、格式和错别字。

不要在结构尚未稳定时沉迷逐字润色。每项修改都应说明它提升了理解、可信度、画面、节奏或场景适配中的哪一项。

## 接收反馈后再修订

用户反馈“太 AI”“太平”“太重”“不像我”时，先判断反馈指向哪个维度：

- **结构**：信息顺序、论证、叙事推进或段落密度。
- **声音**：读者距离、词汇、句长、幽默、判断与细节选择。
- **情绪**：触发事实、叙述距离、强度、行动冲动、限度或结尾余波。
- **事实**：细节、因果、引语、时间和材料边界。
- **场景**：读者、平台、可读时长、行动要求和正式程度。

先用一句话复述准备调整的维度，再局部或结构性修改。不要只把“更有情绪”理解成加形容词，也不要把“更像我”理解成加入虚构经历或口头禅。

需要给出或核对具体改写标准时，读取 [rewrite-examples.md](rewrite-examples.md)。选择最接近任务的一到两个案例，复用编辑动作，不复制其中虚构情境、细节或句子。

若需要做“太平/无聊”诊断，读取 [reader-momentum.md](reader-momentum.md)，并在修改前先指出主要故障属于期待、阻力、变化、具体性、节奏还是回报；如果是首次起草，也先选择阅读体验档位，不要默认使用温吞的通用语气。
